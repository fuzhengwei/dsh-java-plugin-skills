# 最终交付清单（Delivery Checklist）

> 来源：青苔记账案例三轮排查修复的教训。三个漏网问题——弹层关不掉（UI 层没实测）、鉴权误伤 AI 代理（改动后没跑回归矩阵）、Agent 卡死（不知道 DSH 已知问题）——全部会被本清单拦住。
> 用法：阶段 4 交付前，先跑 `scripts/delivery_check.sh`（自动项），再逐条过手工项。**全部打勾才能交付。**

## 一、自动化检查（`scripts/delivery_check.sh` 覆盖）

```bash
bash <skill_path>/scripts/delivery_check.sh [应用地址] [DSH地址] [pluginId] [写探测路径] [读探测路径]
# 默认: http://127.0.0.1:18081 http://127.0.0.1:8090 <pluginId必填> /api/ledger/transactions /api/ledger/summary
```

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | DSH 探活 | HTTP 200 |
| 2 | 应用探活 | HTTP 200 |
| 3 | 插件状态 | ACTIVE |
| 4 | 写接口鉴权 | 无 token POST 返回 401（若应用有 token 机制） |
| 5 | 读接口探活 | HTTP 200 且返回合法 JSON |

**探活时机红线**：所有地址必须是**交付前刚刚探活**的——沙箱会回收进程，历史地址不作数。脚本发现 DOWN 就先拉起再重跑。

## 二、手工必验清单（脚本测不了的部分）

### 功能层
- [ ] **每个工具 ≥1 条自然语言触发实测**（`agent_stream.sh`），核对 step_break 里 toolName 正确、回答数字与工具返回一致
- [ ] 写操作全流程：真实写入 → 汇总联动 → **重启还原种子数据**
- [ ] 边界拒绝用例：负数/0 金额、非法分类、非法日期、无/错 token——**全部应被拒**（青苔记账曾 5 个全穿透）

### UI 层（必须真实浏览器点击，curl 测不出"弹层关不掉"这类 bug）
- [ ] 用 agent-browser 走一遍核心用户路径：打开页面 → 核心交互（弹层/抽屉/表单）→ 关闭 → 提交 → toast/联动
- [ ] **分域设计语言检查**：设计语言卡已随设计稿产出（主色/背景材质/形状母题/标志性元素/气质关键词 3 个）并**随 README 交付**；页面有贯穿全页的标志性视觉母题；**与库内最邻近 2~3 个案例逐一对比，差异点（辅助色/材质/布局/母题至少两项）已明确列出**，不撞脸；打开页面 3 秒能说出"这是哪类产品"；AI 面板配色跟随本应用设计语言（规范见 ui-design-guide.md 1.5）
- [ ] **AI 气泡 markdown 渲染检查**：AI 面板问一条会触发列表/加粗的问题（如"推荐几款"），确认 `**加粗**`、`- 列表`、`###` 标题被渲染成真实排版，而不是星号裸显（外卖案例曾整屏星号；规范与代码见 ui-design-guide.md 第五节）
- [ ] **视觉/拍照类案例加验**（P100~P104 适用）：拍照/上传交互真实可用（拖拽/选择文件）；试一试样张识别结果与人工标注一致、带置信度展示；扫描识别动效正常；免责声明在页面固定位置可见；「识别结果 → 预置库数值 → 汇总看板」联动正确（识别一餐后当日摄入环图同步更新）
- [ ] 显隐切换检查：所有用 `hidden` 属性控显隐的元素，确认 CSS 没有写死 `display` 覆盖它（修复模式：全局 `[hidden]{display:none!important}`）
- [ ] 每个按钮/入口实际点一遍，无 JS 报错、无静默无效
- [ ] **agent-browser 排障技巧**：点击无效时先 `elementFromPoint`——返回 null = 坐标在视口外（自动化浏览器视口仅 ~650px 高），先 `scrollIntoView` 再点；不要误判为应用 bug

### 回归矩阵（改了全局机制必跑——Filter/拦截器/统一异常处理/中间件）
改全局机制 = 影响所有链路，**新规则生效 + 旧链路完好两侧都要验**：

| 侧 | 用例（以鉴权 Filter 为例） |
|---|---|
| 新规则生效 | 带正确 token 写入成功；无/错 token 被拒 |
| 旧链路完好 | 页面正常流（读接口、静态资源）；**AI 代理 SSE 仍通**（`POST /api/assistant/stream`）；Agent 端到端仍通 |

> 血泪案例：青苔记账给所有非 GET 加 token 校验，把浏览器直连的 AI 代理也拦了，用户看到「无法连接 AI 财务助手」。**全局 Filter 必须按路径收窄作用域，回归必须覆盖每条既有链路。**

## 三、DSH 已知问题（交付说明里提醒用户）

| 问题 | 表现 | 应对 |
|---|---|---|
| 流式请求被强断后 Agent 卡 RUNNING | 后续请求报「正在执行上一条消息」 | 无 stop 端点，重启 DSH 恢复；自动化脚本里不要强杀流式请求进程 |
| step_break 事件重复推送两次 | 前端看到两次工具调用展示 | 单次写入只一条 tool_result，未重复执行；展示层去重即可 |
| 沙箱 SERVER_PORT 注入 | 应用绑到随机端口 | 启动显式 `--server.port`（详见 runtime-pitfalls.md） |
